# i18n

**`language`** 라는 이름의 변수 컬렉션에 있는 번역용 STRING 변수를 관리하는 Figma 플러그인.
플러그인 UI에서는 이 변수를 **토큰**(영어 UI: token)이라고 부르고, 토큰의 기준 레이어를 **key 레이어**라고 부른다.
컬렉션의 모드가 언어(예: en, ko)이고, 변수 그룹은 캔버스의 **섹션 > 섹션 > 레이어** 구조를 따른다.

## 설치

1. Figma 데스크톱 → **Plugins → Development → Import plugin from manifest…**
2. 이 폴더의 `manifest.json` 선택
3. **Plugins → Development → i18n** 로 실행

빌드 단계 없음 — `code.js`와 `ui.html`을 그대로 로드한다.

## 기능

### 아무것도 선택하지 않았을 때

토큰 검색(이름·ID·값). 결과를 클릭하면 그 토큰의 **key 레이어로 이동**한다 (다른 페이지면 페이지도 전환).
key 레이어가 없는 토큰은 "key 레이어 없음"으로 표시된다. 결과는 처음 100개까지 보이고 검색어로 좁힌다.

### 토큰이 없는 텍스트 레이어를 선택했을 때

- "연결된 토큰 없음" 안내와 **토큰 생성하기** 버튼이 보인다 (연결된 레이어와 헷갈리지 않도록 폼은 바로 열지 않음).
- 버튼을 누르면 **새 토큰 입력 폼**이 열린다. 기본 모드 값은 레이어의 현재 텍스트로 미리 채워진다
  (컴포넌트 텍스트 속성이면 그 값). 기본 외 모드는 비워 두면 `--`(미번역 표시)가 된다 (placeholder도 `--`).
- 토큰 검색은 어디서나 **전체 토큰** 하나의 범위다 (그룹 구분 없음). 검색어가 없으면 전체를, 많으면 처음 100개를 보여 준다.
- **다른 토큰 값 가져오기**(보조): 기존 토큰을 검색해 고르면 그 **값만** 폼에 복사한다.
  기존 토큰을 연결하는 것이 아니며, 만들어지는 토큰은 새 ID를 가진 별개의 토큰이다.
- **생성 및 적용**으로 토큰을 만들고 해당 레이어에 연결한다.

### 토큰이 연결된 텍스트 레이어를 선택했을 때

- **값 편집** — 설명과 모든 모드 값을 편집. *확인*이 저장, *취소*·플러그인 닫기·다른 레이어 선택은 폐기.
- 아래 세 패널이 각각 상태·동작·설명을 함께 보여 준다 (아이콘 포함):
  - **토큰** — `토큰 교체`: 해당 레이어에 다른 기존 토큰을 연결 (전체 토큰 목록, 이름·ID·값 검색).
  - **Key 레이어** — 선택하는 즉시 상태를 확인해 표시: 해당 레이어가 key 레이어 / 다른 레이어에 있음 /
    **찾을 수 없음**(삭제되었거나 다른 토큰에 연결됨 — 경고) / 지정 안 됨.
    동작: `key 레이어로 이동`(이동 후 "이전 레이어로 돌아가기"), `해당 레이어를 key 레이어로 지정`, `다른 레이어 선택…`.
  - **연결** — 해당 레이어가 key 레이어면 `토큰 삭제`(두 번 눌러 확정): 이 페이지에서 토큰을 쓰는 모든 레이어의 연결을
    해제한 뒤 토큰을 삭제. 아니면 `해당 레이어에서 연결 해제`: 해당 레이어만 해제하고 토큰은 유지.
    어느 경우든 해제된 레이어는 현재 보이는 텍스트를 유지한다.

### 여러 레이어를 선택했을 때

선택한 텍스트 레이어들을 한 번에 같은 변수로 교체할 수 있다.

### 페이지·섹션 바로 아래 레이어를 선택했을 때 — 번역 테이블

화면 프레임처럼 **페이지나 섹션 바로 아래**에 있는 레이어를 선택하면, **key 레이어가 그 안에 있는 토큰** 수를 보여 주고
(그 레이어에서 사용만 하고 key 레이어는 다른 곳에 있는 토큰은 제외)
**번역 테이블 만들기**를 제공한다.

- 테이블은 `i18n-table` 컴포넌트의 instance로, 선택한 레이어 **오른쪽 100px**(같은 페이지/섹션)에 만들어진다.
  토큰 하나당 `i18n-row` instance 한 행이 `i18n-slot` 안의 `i18n-rows` 프레임에 들어가고, 행은 원본과 **같은 변수에 연결**된다
  (row 템플릿의 `value` 텍스트 속성에 연결 → 모든 열의 텍스트가 이 속성을 표시).
- 행이 많아도 견딘다: 변수 1000개 기준 테이블 생성 약 7초, 변경 없을 때 확인 0.2초, 행 몇 개 추가·삭제 약 1–2초,
  언어 추가 시 열 추가 0.3초(행별 작업 없음). 200행이 넘으면 진행 안내가 뜬다.
- 열은 `language` 컬렉션의 모드마다 하나씩이며, 헤더에는 모드 이름(Korean, English …)이 들어간다.
  모드가 늘거나 줄면 **두 템플릿 컴포넌트에 열이 함께 추가/제거**된다. 행의 각 열에는 해당 모드가 지정되어 있어 그 언어 값이 보인다.
- 템플릿(`i18n-table`, `i18n-row`)은 파일에 같은 이름의 컴포넌트가 있으면 그것을 쓰고, 없으면 **현재 페이지에 새로 만든다**.
  템플릿을 지운 경우 패널에 경고와 **템플릿 복구** 버튼이 뜬다 (현재 페이지에 다시 만들고 이 페이지의 테이블을 다시 연결).
- 이미 테이블이 있는 레이어를 선택하면 **테이블 업데이트 / 테이블로 이동**, 테이블을 선택하면 **테이블 업데이트 / 원본 레이어로 이동**.
- **업데이트**: 변수 값은 텍스트 연결 덕분에 즉시 반영된다. 행(원본에 변수 추가·제거)과 열(모드 변경)은 플러그인이 열려 있는 동안
  **현재 페이지의 테이블만** 2초마다 확인해 맞춘다. 다른 페이지의 테이블은 그 페이지를 열 때 맞춰진다 (파일 전체를 매번 훑지 않기 위함).
- 테이블의 행 텍스트는 변수 정리 검사에서 제외된다 (실제 사용처가 아니라 복사본이므로).
- CSV 가져오기·변수 정리·테이블 작업은 순서대로 하나씩 실행된다 (동시에 실행되지 않음). 큰 CSV는 진행 안내가 뜨며,
  값 1000개×2언어 변경은 연결된 텍스트 수에 따라 10초 안팎 걸릴 수 있다 (Figma가 연결된 모든 텍스트를 갱신하는 시간).

### 헤더 버튼

- **CSV 내보내기 / 가져오기** — 아래 CSV 형식 참고. 가져오기 후 결과 보고서 표시.
- **변수 정리** (버튼: *토큰 정리 · 현재 페이지*) — 현재 페이지를 검사해 하나의 보고서(제목에 페이지 이름)로 보여 준다. 각 항목을 보고서를 벗어나지 않고 바로 해결할 수 있다:
  1. **key 레이어가 없는 토큰** → key 레이어 재지정 (토큰 이름 앞에 `⚠️` 표시).
     기록된 key 레이어가 사라졌으면 **항상 이 목록에 표시**된다. 정리가 다른 레이어를 key 레이어로 자동 지정하지 않는다.
     이 페이지에서 **아직 쓰이는** 토큰만 여기 나오고 `N곳 연결됨` 배지가 붙는다 (재지정 권장).
     이 페이지에서 쓰이지 않는 토큰은 별도의 **사용되지 않은 토큰** 섹션에 나온다 (보통 삭제해도 안전 — 다른 페이지에서
     쓰일 수는 있음). 두 섹션 모두 재지정·삭제 버튼이 있다.
     연결된 변수를 삭제하면 한 번 더 확인(`N곳 해제 후 삭제`)한 뒤, 이 페이지의 연결을 모두 해제하고 삭제한다 —
     다시 정리를 돌리지 않아도 끊긴 연결이 남지 않는다.
  2. **변수 연결이 끊긴 텍스트 레이어** → 기존 변수 연결 또는 새로 만들기
  3. **번역이 누락된 토큰** (`--`이거나 빈 모드가 있음)
  1·3번 항목을 누르면 캔버스에서 토큰을 선택하고(이 페이지의 key 레이어, 없으면 화면 중앙에서 **가장 가까운** 사용처 —
  번역 테이블 행 제외) 일반 **편집 화면 전체**(설명·값·key 레이어·연결)를 연다. 상단의 `정리 결과로 돌아가기`로 돌아오면
  해결된 항목(값을 채움, key 레이어 지정, 삭제)은 목록에서 빠진다. 이 페이지에서 쓰이지 않으면 **다른 페이지를 찾아**(key 레이어가
  기록된 페이지부터) 그 페이지로 이동해 레이어를 선택한다. 파일 어디에서도 쓰이지 않을 때만 보고서 안의 편집기(값·설명)로 연다. 2번 항목은 눌러서 해당 레이어로 이동.
- **언어 토글** — `한국어 | EN` (기본 한국어).

## 변수 이름 규칙

- 이름 = `그룹 경로/ID`. 그룹 경로는 가장 가까운 섹션(최대 3단계)과 첫 비섹션 레이어로 만들고
  (`section-A/section-B/layer-C`, 페이지 이름은 제외), 각 세그먼트는 `dashClean` 규칙으로 정리한다.
  실제 문자(라틴·그리스·키릴·아랍·태국·한글·가나·한자)와 숫자, `-`만 남기고 공백·문장부호·화살표·이모지는 제거.
- ID = 소문자·숫자 6자 무작위 값. 변수 정리에서 한 번 부여되면 다시 바뀌지 않는다.

## CSV 형식

열 순서: `1st Section`, `2nd Section`, `3rd Section`, `Layer Name`, `Variable Name`, `Description`, 이후 모드별 1열.

- 가져오기는 `Variable Name`(6자 ID)으로 변수를 찾는다.
- `Description` 열은 **헤더 이름으로** 찾으므로 이 열이 없던 예전 CSV도 그대로 가져올 수 있다(설명은 유지).
  따라서 `Description`이라는 이름의 모드는 만들 수 없다. 빈 칸은 설명을 지우고, 열이 없으면 건드리지 않는다.
- 6번째 열부터 `Description`이 아닌 헤더는 모드이며, 없는 모드는 새로 만든다.

## 노드 지원

- 일반 텍스트 레이어: `setBoundVariable('characters', …)`로 연결.
- 컴포넌트 인스턴스의 TEXT 속성으로 들어간 텍스트: 속성을 통해 연결(`setProperties` + `createVariableAlias`).
  텍스트 레이어를 선택하든 인스턴스를 선택하든 둘 다 해석한다.
- 섹션 구성은 사용자가 캔버스에서 직접 관리한다. 플러그인은 `SECTION` 조상을 읽기만 하고 섹션을 만들거나 바꾸지 않는다.
- 현재 페이지만 대상으로 한다(`loadAllPagesAsync` 없음).
